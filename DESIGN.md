# Karvan design system

Read this before building or changing any page. If something here is wrong, fix this file first, then the code.

## 1. Identity

Karvan moves users from one panel to another, and their configs keep working. The panel should look like the tool it sits next to: a clean operator console in the style of the Cloudflare dashboard, built on Cloudflare's Kumo components.

- **Mark ("Merge"):** two overlapping rounded squares in white on a Kumo-blue rounded tile, with the overlap filled. One panel, another panel, and what they share. Source of truth: `web/src/components/brand/Mark.tsx` (viewBox 64, tile radius 14, stroke 3.2). `web/public/favicon.svg` and `docs/brand/karvan-mark.svg` are static copies with the blue written as `#056dff`.
- **Name:** "Karvan" in English, "کاروان" in Persian, set in Vazirmatn semibold next to the mark (`Wordmark.tsx`). Never stretched, outlined or given effects.
- **Mood:** calm, flat and exact. White and grey surfaces, hairlines, one blue.

### Panel logos
The overview and every panel name show the Marzban and PasarGuard logos to say which panels Karvan works with. Both projects are AGPL-3.0, like Karvan; the logos are used only to name them, never to suggest they endorse Karvan.
- Marzban: its logo path, inline in `components/panels/PanelLogo.tsx`, drawn in `currentColor`.
- PasarGuard: its own transparent logos from its dashboard (`dashboard/public/statics/favicon/`, AGPL-3.0), resized to 128 px: the dark drawing `logo-dark.png` as `components/panels/pasarguard-light.png` for the light theme, the light drawing `logo.png` as `pasarguard-dark.png` for the dark theme. No tile behind it, like Marzban's.

### Where boldness goes
Only one place per screen gets the memorable treatment:
- Sign-in: the blue side with the wall of hexagonal columns.
- Every other page: the content itself. Chrome stays quiet.

## 2. Color

Karvan uses Kumo's palette as it ships, with one change (subtle text one step darker in light mode, `#6b6b6b`, because Kumo's `#737373` reads under 4.5:1 on its own tinted surfaces): neutral greys for surfaces and text, Kumo blue as the brand, Kumo's status colors. Components use Kumo semantic classes (`bg-kumo-base`, `bg-kumo-tint`, `text-kumo-subtle`, `border-kumo-hairline`, `bg-kumo-brand`, ...).

`web/src/styles/tokens.css` holds the only color Karvan adds:

| Token | Value | Use |
|---|---|---|
| `on-brand` | white | text, icons and marks drawn on `bg-kumo-brand` |
| `chart-1` to `chart-5` | Kumo's chart palette: blue, amber, pink, purple, teal (light and dark values from `ChartPalette.categorical`) | chart series, in this order; the first series of every chart is blue |
| `chart-grid` | Kumo's neutral chart fill (light and dark) | grid lines and axis ticks |
| `wall-shade` | Tailwind's blue-900, as in Kumo's dark info banner | the shade on the sign-in wall; the wall mixes the brand blue toward it and toward `on-brand` at run time |

**No color literal anywhere else** in `web/src` (the floor check fails the build). If a new color is truly needed, add a token there and a row here.
Kumo's sixth chart color is an orange; Karvan never uses it (no Cloudflare orange). A chart never needs more than five series; more become "Other".
The chart and wall tokens sit in a `@theme static` block: charts pick a color by number at run time (`var(--color-chart-3)`) and the wall reads its colors from script, which Tailwind's class scan cannot see, so the variables are always emitted.

- `text-kumo-brand` is Cloudflare orange in Kumo. Blue text (links, the current step) uses `text-kumo-link`, Kumo's link color, which reads 4.5:1 in both themes; `text-(--color-kumo-brand)` is for icons and marks only (it reads 3.3:1 on the dark page).
- Status is never shown by color alone. It always comes with an icon and a word.
- **Contrast:** body text at least 4.5:1 on its surface in both themes; large text and icons at least 3:1. Check new pairs before adding a token.

## 3. Type

- **One family: Vazirmatn (variable)** for Persian and English. Its Latin is drawn to sit with its Persian, so a Persian sentence with a username in it reads as one voice.
- **JetBrains Mono** only for machine values: UUIDs, tokens, ports, paths, IPs, commands. Drawn without ligatures, so `://` and `->` read exactly as typed.

| Step | Size / line-height (en) | fa | Weight | Use |
|---|---|---|---|---|
| display | 28 / 36 | 28 / 40 | 700 | sign-in tagline only |
| title | 22 / 30 | 22 / 34 | 600 | page title (one `h1` per page) |
| heading | 16 / 24 | 16 / 26 | 600 | card and section titles (`h2`) |
| body | 14 / 22 | 15 / 26 | 400 | default |
| small | 13 / 20 | 13 / 22 | 400 | helper text, meta, table cells |
| tiny | 12 / 16 | 12 / 18 | 500 | badges, counters |

- Sizes live in `web/src/styles/type.css`. Persian runs one step looser in line-height; Vazirmatn's tall forms need it.
- Sentence case everywhere. **No all-caps labels**, no letter-spaced eyebrows.
- Numbers in tables and counters use tabular figures.
- Line length stays under 75 characters for paragraphs.

## 4. Space, radius, elevation

- **Spacing scale (px):** 4, 8, 12, 16, 20, 24, 32, 40, 56. Nothing off-scale, except 2 px optical nudges and 2 or 6 px padding inside small inline elements (badges, keyboard keys).
- **Layout:** sidebar 224 wide (64 when collapsed), top bar and sidebar header 56 high, content gutters 32 (16 under 640). Pages with side information use a main column plus a 352 aside, split by a hairline. Content stops growing at 1400 wide and stays at the start edge, like the dashboard.
- **Controls:** buttons, inputs and selects draw 32 high with a mouse (square buttons 32 × 32), a step under Kumo's base of 36 (`styles/app.css`). On touch screens they draw 36 (owner decision, 2026-10-26: 44 read too big on a phone), and buttons and selects keep an invisible 44 px hit area wherever it does not overlap a neighbour (section 8, Touch).
- **Radius:** 6 for badges and nav rows; 8 for buttons, inputs and cards; 12 for dialogs and the command palette. Pills only for status dots.
- **Elevation:** surfaces are flat, separated by a 1 px hairline. Shadows only on things that float: menus, popovers, dialogs, the mobile sheet, toasts. Cards have no shadow.

## 5. Motion

- Everything that changes state moves a little, so nothing appears or vanishes at once: 150 ms for small things, 200 ms for the desktop sidebar, 220 ms for the mobile sheet, 800 ms for charts drawing in, always ease-out, `transform` and `opacity` wherever they can do it (cheap on weak phones). Nothing bounces. The shared rules live in `styles/motion.css`.
  - Switches: the thumb slides with a transform (Kumo moves it by its edge, which `motion.css` replaces), both ways. Checkboxes and radios: the mark grows and fades in.
  - Menus, selects, popovers and the account menu: fade and scale up from where they open (from 96 %), and back when they close. Dialogs, the palette and the shortcut sheet fade and scale from 90 % and back.
  - The mobile sheet slides in from the start edge (from the right in Persian) while its backdrop fades, and slides back out when it closes. The detail and full list sheets on phones slide up from the bottom and back down, 220 ms. The overview search's panel fades in and out like a menu.
  - The desktop sidebar collapses and expands by its width over 200 ms; its content fades into the new shape. With the content laid out at full width and clipped, labels never wrap on the way.
  - **Closing mirrors opening**, everywhere: whatever opens with motion closes with the same motion backwards, and a dialog keeps the words it was opened with while it fades out.
  - Collapsing sections, sidebar sub-rows, the two-step setup and rule cards (`components/layout/Collapse`): open and close both ways, height through grid rows (0fr to 1fr) with a fade, 150 ms. Height and the sidebar's width are the only layout properties that move; both are short and run only on a press.
  - Tabs: the new tab's content fades in.
  - Toasts slide up and fade in, and fade out.
  - Rows appearing in tables and lists fade in. A badge that changes state fades into the new one.
- **Charts draw in** every time a page shows them (a visit, a reload): a line and the area under it are revealed together from the start of the time axis to its end (left to right in both languages, a CSS clip on the chart's own svg box (never on a group inside it, which some browsers do not clip), starting 200 ms in so it is seen after the card's fade, that moves with the line and ends with no clip at all, so a chart whose data arrive after it mounts still ends fully drawn), bar charts grow up from the baseline, and the meters of bar lists fill from the start edge, 800 ms ease-out. Samples that arrive later (polls, live charts) are drawn in place, without replaying the draw or tweening. Progress meters (wizard steps, read progress, the live view) do not fill in; they show real progress only.
- **Motion runs to its end** even when the work is instant (`lib/motion/use-min-duration`): a refresh icon turns at least once and stops only at the end of a turn; a switch that saves moves to its new place at once and stays busy until its slide is done (it slides back if the save fails); a skeleton stays its 400 ms. Dialogs open only on a press and close only on the operator's choice or a finished action, so their opening always plays out.
- **Loading:** a page or card that has no data yet shows its skeleton for at least 400 ms, then the content fades in over 200 ms, so the change reads as data arriving, not as a flash (`lib/motion/use-first-load`). Refetches and polls never bring the skeleton back; the content updates in place.
- **Skeletons** are flat recessed shapes with a soft light that sweeps across them from the start edge, slow (2 s a sweep, a pause included) and low contrast in both themes (`--color-shimmer` in `styles/tokens.css`), drawn by a transform.
- **Theme change:** the page crossfades from the old theme to the new one over 200 ms with the View Transitions API (`lib/preferences/theme-transition`). Where the browser has no View Transitions, it changes at once.
- Hover colors change at once, never with a transition (Kumo's rule: fading hovers feel slow).
- Motion answers an action (open, expand, confirm, switch) or data arriving. Headers, cards and the shell never slide in on their own.
- The live migration view moves dots only in step with real chunks, and while a backup restore runs, which has no chunks (section 8, Live progress).
- The one exception is the wall on the sign-in page: its columns slide slowly in and out on their own, in calm waves (section 8, Sign-in). It draws at about 30 frames a second and stops when it is off screen.
- `prefers-reduced-motion: reduce`: no transforms, fades or autoplay; transitions and animations shorten to 1 ms. Skeletons have no minimum time and no light, charts appear drawn (no reveal), nothing is held to a minimum, the theme changes at once, and the wall shows one still frame.

## 6. Icons

- Phosphor, `regular` weight: 16 px in sidebar rows and inline, 18 px in the top bar, 20 px in buttons. A few icons on pages near their size budget are Phosphor's own regular drawing inlined (`components/icons/regular`), because the package's icon carries all six weights. Where Phosphor has no match, a small SVG in the same stroke (`app/shell/MenuIcon.tsx`, the phone menu button: three lines, the bottom one shorter at the start edge, mirrored in RTL).
- Icons never stand in for words in primary actions. Icon-only buttons have an `aria-label` and a title or tooltip.
- No emoji in the UI.

## 7. RTL and languages

- `<html lang dir>` is set before first paint (`public/boot.js`). Persian is the default.
- Use logical properties only: `ms-* me-* ps-* pe-* start-* end-* border-s border-e rounded-s rounded-e text-start`. Physical `left/right` classes are a bug. In an RTL flex column `self-start` is already the right edge; do not add `rtl:` overrides to "fix" it.
- Icons that point a direction (arrows, chevrons, sign out) flip in RTL with `rtl:-scale-x-100`. The logo and the panel logos never flip. The sign-in wall is mirrored, so it recedes toward the form in both languages.
- Charts keep time running left to right in both languages, like a graph in a school book; only their labels are Persian. A move from one panel to another reads in the page direction ("Marzban, arrow, PasarGuard" runs right to left in Persian).
- Machine values (UUID, IP, port, path, username, commands) are wrapped in `<bdi dir="ltr">` or `dir="ltr"` and stay in Latin digits.
- A machine value inside a translated sentence (a file, a setting, a command) is marked with backticks in the message, and the sentence is drawn with `CodeText`: the value keeps left to right in mono at about 0.9 em. Left unmarked, `.env` after Persian words reads `env.`.
- Persian text uses Persian digits (۰ to ۹); English uses Latin digits. `src/lib/format` does this; never format numbers by hand.
- Dates: Jalali calendar and Asia/Tehran by default, Gregorian in English unless the operator chooses otherwise. Times say which zone they are in when it matters ("It is 18:40 in Tehran").
- Kumo components that use physical classes get checked in RTL; any broken one gets a wrapper or a workaround in Karvan code instead of being used raw. Known cases: Kumo's Sidebar (not used), the DropdownMenu item `icon` slot (put the icon in the children with `gap-2` instead), Kumo's Table (`text-left`) and InputGroup (`pl-*`, `rounded-l-*`), which Karvan replaces with its own table and search field (section 8, Tables). Kumo's Toast pins its close button with `right-2`, over the start of Persian text: `styles/app.css` moves it to the end edge and gives the text room on that side.

## 8. Components and patterns

- **Kumo first** for leaf components: Button, Input, Field, Select, Switch, Dialog, DropdownMenu, Tooltip, Badge, Toast, CommandPalette. Import each from `@cloudflare/kumo/components/<name>`, and add its chunk name to the `@source` line in `src/styles/app.css`, or its styles are missing.
- The sign-in page stays light: no Tooltip, Dropdown or CommandPalette there. `LanguageSwitch` (one button naming the other language) and `ThemeToggle` (one button) exist for this reason.

### Shell
The Cloudflare dashboard's frame, built from Karvan's own components with logical properties (Kumo's Sidebar uses physical classes):
- **Sidebar header (56 high):** the mark, then the panel switcher where the dashboard has its account switcher: the current panel's logo and name, an up and down chevron. Its menu only chooses: "All panels", then the panels (a warning icon on one that needs attention). Scanning lives on the Panels page.
- **Sidebar body:** a "Search... Ctrl K" field that opens the palette, then grouped rows as dense as the dashboard's: 30 high and 32 apart (on touch 36 high and 40 apart, each hit area reaching its neighbour's), `base` text, 16 px icons in `text-kumo-subtle`, the current row on `bg-kumo-tint` with radius 6. Group labels are `small` and quiet, 16 above them. No Settings or Security rows: they live in the account menu.
  - Groups, in order: Overview and Analytics with no label; Move (Migrations `g m`, Batches `g h`); Subscriptions (Domains and certificates `g d`, then Rules `g l`); Server (Panels `g p`, Backups `g b`). A group holds only built pages, so Domains and certificates joins Subscriptions with its page.
  - Sub-pages: a row with sub-pages is a toggle, not a link: a click opens or closes its sub-rows in place and goes nowhere (the phone sheet stays open). It has a chevron at the end (pointing to the end, down while open) and starts open while one of its pages is shown; the reader can close it. A sub-row navigates (and closes the phone sheet). Its sub-rows indent under its label with a 1 px hairline guide at the start, as in the dashboard's DNS rows; the current sub-row is tinted, not its parent. Analytics has them: Server, then one row per panel. The collapsed sidebar shows only the parent.
- **Sidebar footer:** one button that collapses the sidebar to icons with tooltips; remembered per browser.
- **Top bar (56 high):** at the end, the Safe Mode status (a small badge that opens Settings, like the dashboard's plan badge), a GitHub link (Phosphor's GitHub logo, icon only, opens the repository in a new tab) and the account button. On phones (under 1024) only the menu button at the start and the GitHub link and the account button at the end: the mark and search live in the sheet, and Safe Mode is not shown on phones at all. Under 1024 the bar slides up out of view (a transform, 200 ms) once the page has scrolled down past its height, and slides back on any scroll up (a few px of jitter change nothing), at the top of the page and when focus moves into it; it never hides while the sheet, the palette, a menu or a dialog is open, and a sticky row under it (the analytics toolbar) moves up with it. Desktop keeps it fixed.
- **Account menu:** like the dashboard's, about 192 wide (its time zone submenu may be wider): the username alone at the top (no "Signed in as"), Settings, Appearance (light, dark, same as system), Language (فارسی, English), Time zone (the zones of Settings General, the current one checked; a choice saves as there), Keyboard shortcuts, then Sign out. Language and theme have no buttons of their own in the app.
- **Language change:** wherever it is chosen (account menu, Settings General, the palette, the sign-in page), the choice is saved and the page reloads, so every part of the page, dates and direction included, comes back in the new language at once.
- **Mobile:** the sidebar opens as a sheet from the start edge, 256 wide or 69 % of the screen, whichever is less, with focus inside it and Escape to close. While it is open the page behind it does not scroll; a tall sheet scrolls itself, without passing the scroll on. Its header, like the dashboard's phone sheet: the mark, the panel switcher beside it, and close (X) at the end; under it the search field, then the rows. Menus opened inside the sheet render inside it (the sheet is a modal `<dialog>` in the top layer, so a menu outside it would sit under it and ignore taps). The sheet does not clip them: its rows scroll inside it, so a menu wider than the sheet (the panel switcher's) opens in full over the page, within the screen.
- **Footer:** one quiet row at the end of the content: version, source code, report a security issue.
- **Command palette:** every page, panel, setting, preference and action is reachable from Ctrl K. Migrations (by admin, address and panel) and old link sites (by name, address, domain and port) are listed once something is typed, and read only while the palette is open. The search row ends with an `Esc` key, the way out; the footer keeps the arrow and Enter hints. `?` opens the shortcut sheet, which lists every page with its `g` letter. The palette and the sheet are the one exception to Kumo's always rendered dialogs: each builds all its rows on every shell render, so it mounts when it first opens and opens one frame later (so it still animates in), then stays rendered.

### Page
- **Page header:** a small label above the title when the page sits inside another (the dashboard's breadcrumb), the title, one line of context under it, actions at the end, a bottom hairline across the full width.
- **Cards:** `bg-kumo-base`, hairline ring, radius 8, title row at the top, no shadow, no divider under the title unless the card holds a table.
- **Layer cards** (analytics, grouped facts): Kumo's LayerCard, a tinted title row over a white body, one level only (never a LayerCard inside another).
- **Tables:** a list toolbar across the top; the table in a ringed frame with a tinted header row; rows about 48 high; "..." row menus; a footer that says how much is shown ("Showing 1 to 20 of 340") with previous and next page buttons (`components/data/Pager`; Kumo's Pagination has physical classes and carets that do not turn in Persian). Long lists live on their own page, never on the overview. Under 640 rows become stacked cards, like the dashboard's DNS records on a phone (`components/data/RowCard`): a top line with what the row is at the start and its status badge and "..." menu at the end, the main value (the row's link, which makes the whole card a tap target) with one quiet line under it, the other facts as labelled pairs, and a tinted footer row with the outcome and the time, ending in a chevron.
  - **List toolbar** (`components/data/ListToolbar`), like the dashboard's Workers and Pages list: one joined control, 36 high, inside the overview search's soft halo (a tinted ring a few px outside it). The search input first, then a segment per filter and per sort (the current choice, "Show all" or "Newest first", with an up and down chevron; it opens a small menu with a check on the current choice and each choice's count where Karvan knows it), then refresh where the page has one, every seam shared. Actions such as + sit after the halo. Every list uses it, never a row of separate filter buttons.
  - On phones the group is the search, a filter icon button and refresh. The filter button opens a bottom sheet with each filter and sort as a labelled select. While a filter is on, the filter button carries a count badge and a clear filters icon button joins the group.
  - Built from `components/data`: `DataTable` (the columns, and the card one row becomes on a phone) and `ListToolbar` with its search field (`/` focuses it, Escape clears it). Kumo's Table is not used: it sets `text-left` and stripes its rows.
  - The first column names the row with its logo and links to its page, underlined as in the dashboard. Status cells are an icon in the status color and a word in the default color, like the dashboard's "Active".
  - A short list the server does not page ends with "Showing 2 of 2" and no pager.
  - `/panels`: the list toolbar has the search, a filter (ready, needs attention, with counts) and sort (name, newest). Its refresh button scans this server and refreshes the list in one action (named so), and its toast says what the scan found. There is no separate scan button.
- **Detail pages:** title with status badges, underline tabs, content cards, an aside for facts and quick actions.
- **Settings pages:** one page with underline tabs, one route per tab. Each setting is a row: title (with its status badge after it when it has one) and one line of description at the start, the control at the end, rows split by hairlines. Under 640 a wide control (a select) drops below the text, and a switch stays at the end of the title line, as in the dashboard's settings on a phone; when the title is too long to share the line, the switch moves under the title, before the description.
- **Aside:** short status blocks, each a heading, a status badge and one sentence, divided by hairlines.
- **Facts** (`FactList`): label at the start, value at the end, rows split by hairlines. A value too long for the rest of its row (a path on a phone) moves under its label.
- **Panel names:** always with their logo (`PanelLabel`). A move between panels is shown as the source logo, an arrow and the destination logo (`MoveLabel`), in lists, the wizard, the live view, reports, rules and backups.

### Overview
Laid out like the dashboard's account home, top to bottom:
- **Heading, no header:** no title, date line or actions. One fixed line, centred, in `display` size, as the dashboard's "What are we building today?": "What are we moving today?". It sits 56 px under the top bar (48 on phones), the search 32 under it and the columns 32 under the search. The page's `h1` ("Overview") is for screen readers only. New migrations start from the Migrations page and the palette.
- **Search** (`features/overview/search`), like the dashboard home's: a wide input (radius 8, the magnifier at the start, "Search") inside a soft tinted halo, a second rounded ring a few px outside it. As wide as the columns under it, the input 44 high inside the halo. Focus does not open the palette: a panel drops right under the field, as wide as it, with a hairline ring and a soft shadow (it floats). Empty, it lists Recents (the pages this browser opened, each with its section's icon, its name, a dash and its section in quiet text); typed, the palette's own groups (pages, panels, migrations, batches, rules, settings, actions), found the same way. The highlighted row is tinted with an arrow at its end. A quiet footer names the keys: arrows to move, Enter to choose, Esc to close. It is a combobox with a listbox (Kumo's Autocomplete fills the field with the chosen row and passes no name to its input, so Karvan builds this one).
- **Three columns:** Panels, Migrations and Recents. Each has a quiet title (a link with a chevron when its page exists) and at most 3 short rows (the last 3 entries) split by hairlines, each row a link with a chevron at the end. A column with nothing in it says so in one line on a tinted box. Columns stack on phones.
  - Panels: logo, name and its status; the last 3 registered. Migrations: the move (`MoveLabel`), the admin, the state, then how many users moved and when.
  - Recents: the last pages this browser opened, newest first, at most 3, named in the current language as "section / page" ("Panels / logo name"). Kept in localStorage as paths inside the hidden path, never the hidden path itself.
- **Summary:** a heading, then three cards that differ in shape: users moved (the number, a meter of moved and skipped, the jobs by outcome), Safe Mode (status badge and its facts) and Old links (the count of rules and the way in to Rules).
- **Analytics:** this server only (the panel databases live on the analytics pages), always live (polling), with no range and no refresh: the heading, then compact cards in two columns (one on phones): CPU, Memory, Network, Disks and This server's facts. The section loads after the rest of the page.
  - A card with more to show is one button (the whole card, keyboard and focus ring included) that opens its detail; there is no "..." menu. A card that already shows everything (Disks, the facts) is not pressable and has no hover.
  - **Detail:** on desktop a centred dialog (768 wide, the title at the top start, X at the top end), on phones a bottom sheet with rounded top corners that slides up and scrolls inside. Under the title one quiet line, "Trend and leading contributors for the selected time", then a ringed card with the detailed chart (its legend, at most five series, then "+N more"), then a ringed card with the leading contributors as a bar list: per core for CPU, used, cache and swap for memory, per network card.
- **No panels yet:** one empty state with both logos and "Scan this server" takes the place of the columns and the summary.

### Analytics
- Laid out like the dashboard's zone analytics, with no title block (the `h1` is for screen readers): one toolbar row that sticks under the top bar, a hairline under it. At its start the tabs as a segmented control (`components/layout/SegmentTabs`: a tinted rounded group, the open tab raised on the base color with a hairline ring; Server, then one per panel with its logo). On phones, and on desktop when the segments would not fit, they become one button (`components/layout/TabSwitcher`): the current tab's icon or panel logo, its name and an up and down chevron; it opens a list of every tab (Server and each panel with its logo, a check on the current one), and choosing one opens that tab with the same range. At its end the range button (a calendar icon, Live, 1 hour, 24 hours, 7 days, 30 days). No "..." menu. No refresh: the page is always live. Then a row of compact cards (up to five in a row on desktop, two on tablets, stacked full width on phones), the detailed charts in two columns (one on phones), then the lists ("Top ...") in two columns.
- The range lives in the address (`?range=24h`) and carries across tabs, so two tabs compare the same time. Polls run only while the tab is visible and do not count as activity.
- **Compact card** (`components/charts/CompactCard`, the overview's and the analytics row's): the label small at the top start, the value large under it with the change right after it on the same line, then one small quiet line ("2 cores", "of 12 GB"). The change is Phosphor's diagonal trend arrow (ArrowUpRight up, ArrowDownRight down, mirrored in RTL) and the percent, in Kumo success or danger by whether the move is good for the operator (CPU, memory and connections rising are danger), never color alone; no figure where there is nothing to compare. The change compares the latest value with the first one in the window (the range, or what Karvan holds live). The chart fills the bottom of the card edge to edge (56 high in the analytics row, 72 on phones, 120 on the overview): no axes, ticks or grid, only the line and its light area, with the first and last segment dashed (an edge bucket is not complete). A metric with no data draws a faint wide wave with a few soft hills and a small rounded "No data" pill in the middle. On the analytics pages the compact cards are not pressable: their metric has its own detailed chart below.
- **Detailed chart cards:** a layer card with a tinted title row ("CPU", "Network", ...; it wraps to two lines on a phone rather than cut) and, where a chart can be split, a "Group by" select at its end (cores or all of them; direction or the total). Controls in a title row are small, as in the dashboard: 28 high with 13 px text and a small chevron (square buttons 28 by 28), on phones too, and they never make the row taller than its title; on touch they keep an invisible 44 px high hit area inside the row. The body holds the legend and the chart.
- **Top lists:** a layer card per list (admins, largest tables, nodes, subscription apps) with the bar list; its title row ends with an expand button and a "..." menu (sort by size or by name). Expand opens the full list in a dialog on desktop and a bottom sheet on phones, with the list toolbar at its top: the search, a sort ("Proportion", "Name") and a count ("25 items").
- **Time series:** thin 1.5 px lines without an area, the first and last segment dashed, dashed grid lines in `chart-grid`, four or five round ticks (whole numbers for counts), axis labels in `small` and `text-kumo-subtle`, the y labels at the left. Labels are HTML over the SVG, so Persian digits and words read in the page direction while time runs left to right. Hovering, touching or moving with the arrow keys (the chart is a slider) shows a crosshair and a tooltip with the time and every series. Missing samples leave a gap, never a line to zero; a lone sample is a dot.

  - Move: the two panels as tiles (logo, name, a number), a dashed arc between them that runs in the page direction. It fills the side; its foot and its top are never in the frame. Each cap has a round plug in its middle, drawn in the same perspective. Each column slides slowly out of the wall and back in on its own, in calm waves that cross the wall (cycles of 7 to 20 seconds, never all together, nothing sudden).
- Its colors are Kumo's: the caps in the brand blue, the shaded sides and the gaps between columns mixed toward a deep blue (`--color-wall-shade`, Tailwind's blue-900, which Kumo's dark info banner uses), thin `on-brand` lines for the cap edges that face the light and for the plugs. Light comes from the top start, so the sides that face down and toward the end are darker; a settled cap sits a little in shade and one that stands out catches a little light. Columns further away sink into a deeper blue with less contrast, so the text over the far corner stays calm and readable.
- It is drawn on a canvas at about 30 frames a second, and only while it is on screen; with reduced motion it is one still frame. It is a lazy chunk with its own budget, loaded after the form, and it fades in over 700 ms when it arrives instead of popping up.
- Under 1024 px only the form side shows, filling the screen, and the language and theme buttons move into its top bar. There is no wall on phones, and its code is not even loaded.

### Behavior
- **Kumo's own rules** (kumo-ui.com/skill): content text is 14 (15 in Persian), only headings are larger; sentence case; no letter spacing changes; `font-semibold` for headings and `font-medium` for bold inline text, never `font-bold`; related text sits closer than the block it belongs to; a ring instead of a border next to a shadow; nested corners are concentric (outer radius = inner radius + padding); icons line up with the first line of text; inline mono text at about 0.9 em; a hairline under anything sticky; collapsing content keeps its size while it closes; dialogs are always rendered and opened with `open`, never mounted on demand.
- **Primary action:** one per area, `variant="primary"`. Everything else is secondary or ghost.
- **Loading:** skeletons shaped like the content, never spinners for content. Spinners only inside a button that is working.
- **Empty states:** an icon, what is missing, why, and one action (`components/feedback/EmptyState`: Kumo's Empty in shape, with the card radius and the heading size of section 3).
- **Errors:** say what happened and how to fix it, in plain words. Never show raw server errors. Errors do not apologize.
- **Problems Karvan found** (a panel finding, why it cannot stop a panel): what is wrong, then how to fix it, then the machine value it is about (a path, a revision, a table) when there is one. The raw error text behind it never shows.
- **Dangerous actions:** need the name typed to confirm (delete, restore, turning Safe Mode off). Deleting a draft that never ran asks once without typing, since no panel changes.
- **Copy:** every Copy button is `components/text/CopyButton`, sized to its icon and label: the Clipboard API on HTTPS, a hidden field and the copy command on plain HTTP (the browser gives the Clipboard API only to secure pages). A toast says it was copied, or, when the browser refuses, that the text is selected to copy by hand.
- **Status badges:** icon + word + Kumo status color (`StatusBadge`). Kumo's warning text on its own tint is under 4.5:1, so a warning badge keeps the word in the default color and the icon in the warning color.
  - A migration's state uses the same pieces: done is success, failed is danger, running is info, interrupted is warning, drafts and rolled back jobs are neutral.
- **Touch:** controls draw 36 high on touch screens too (owner decision, 2026-10-26; it replaces the 44 px drawn size). Each button, select trigger and link button keeps an invisible 44 px hit area (an `::after` 4 px past its edges, `styles/app.css`) wherever it does not overlap a neighbour: inside a joined group it grows only up and down. A control drawn smaller (a switch, a sidebar row) keeps its hit area with a `::before`, as far as the next control allows. Inputs cannot carry one and stay at 36.
- **Disclosures toggle:** whatever a click opens (a menu, a submenu such as Appearance, Language or Time zone, a select, a collapsible section, a sidebar group) a second click on the same trigger closes. A submenu the pointer opened by hovering stays open on the first click (`components/menus/use-sub-toggle`).
- **Every page is built:** each sidebar item has its route and its `g` letter; there are no inert "Soon" items or tabs.

## 9. Writing

The voice is plain and natural, like a well-made Iranian product site: not robotic, not stiff, not salesy, and not chatty. Nobody reading it should think a machine wrote it.

- **Short.** Say it once. No extra explanation, no "coming in the next version" notes, nothing that repeats what the screen already shows. If a line can go, it goes.
- **No hype.** No big promises, no "seamless", no "without any hassle".
- A button says what happens: "Sign in", not "Submit". The same action keeps the same name in the toast that confirms it.
- Name things the way the operator does ("users", "panels"), not the way the code does.
- **Persian** is standard written Persian, kept simple, and written in Persian, not translated word for word. Polite plural verbs ("وارد کنید", "دوباره امتحان کنید"), written forms ("را", "نمیشود"), no slang. Common technical words stay (پنل، کانفیگ).
  - Never use the half-space (U+200C). "می" and "نمی" join the verb: "میرن", "میشه", "نمیشه". Plural "ها" joins after a letter that does not connect (کاربرها) and takes a space after one that does (پنل ها).
  - A spaced "ها" can wrap onto the next line in a heading; reword it if it does.
  - No hamza on he (U+0654): "نسخه بعدی". No guillemet quotes, no Persian semicolon, no ellipsis character (use three dots), no em or en dash.
- **English:** plain, short, sentence case. Straight quotes and apostrophes only, no em or en dashes, three dots instead of the ellipsis character.
- No exclamation marks, no filler ("Please") unless leaving it out would sound rude.
- `scripts/check-floor.sh` fails on any of the banned characters in tracked files.

## 10. Do and don't

| Do | Don't |
|---|---|
| Hairline borders for structure, flat cards | Soft shadows under cards, gradients, glows and glass as decoration |
| One bold thing per screen | Decoration competing with content |
| Kumo blue for the brand and primary actions | Cloudflare orange anywhere, or extra brand colors |
| Real content and real data in every state | Lorem ipsum, fake numbers, emoji |
| Sentence case, quiet labels | All-caps eyebrows, "01 / 02 / 03" markers on things that are not steps |
| Logical CSS properties | `left`, `right`, `ml-*`, `pr-*` |
| Charts with their numbers in text and a table for screen readers | A chart as the only place a value lives |
| Hover colors that change at once | `transition-colors` on hover |
| Panel logos next to panel names and moves | A bare "PasarGuard" or "Marzban" in lists |
| Test at 360 and 1440 px, fa and en, dark and light, keyboard only | Shipping a page seen in one language and one theme |
